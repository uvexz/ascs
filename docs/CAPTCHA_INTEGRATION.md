# Cap.js CAPTCHA 集成说明

本项目已集成 Cap.js CAPTCHA 验证系统，用于防止垃圾评论和机器人攻击。

## 功能特点

- **轻量级**: 基于 SHA-256 工作量证明的现代 CAPTCHA 替代方案
- **隐私保护**: 不收集用户数据，完全在客户端运行
- **快速验证**: 通常在几秒内完成验证
- **易于集成**: 简单的 API 和组件

## 技术实现

### 后端组件

1. **API 路由**:
   - `/api/challenge` - 创建新的验证挑战
   - `/api/redeem` - 验证挑战解决方案

2. **评论验证**:
   - 在 `/api/comments` 路由中添加了 CAPTCHA 验证
   - 提交评论前必须完成 CAPTCHA 验证

### 前端组件

1. **Cap Invisible Mode**:
   - 自动加载 Cap.js 脚本
   - 使用 invisible mode 进行后台验证
   - 处理验证完成事件

2. **用户体验**:
   - 默认显示"开始安全验证"按钮
   - 验证完成后显示"提交评论"按钮
   - 验证完成提醒 3 秒后自动消失
   - 提交后自动重置验证状态

## 配置选项

Cap.js 服务器实例在 API 路由中初始化：

```typescript
const cap = new Cap({
  // 可以配置存储选项，默认使用内存存储
})
```

## 使用流程

1. 用户可以随时点击"开始安全验证"按钮（无需先填写表单）
2. Cap.js 在后台进行工作量证明验证
3. 验证完成后显示成功提醒（3秒后自动消失）
4. "开始安全验证"按钮变为"提交评论"按钮
5. 用户填写评论表单（姓名和内容为必填）
6. 用户点击提交评论
7. 后端验证 CAPTCHA token 并创建评论

## 安全性

- 使用 SHA-256 工作量证明算法
- 每次提交都需要新的验证
- Token 有时效性，防止重放攻击
- 客户端和服务端双重验证

## 故障排除

### 常见问题

1. **CAPTCHA 不显示**:
   - 检查网络连接
   - 确认 CDN 可访问
   - 查看浏览器控制台错误

2. **验证失败**:
   - 确认 API 路由正常工作
   - 检查服务器日志
   - 验证配置参数

3. **性能问题**:
   - 检查客户端性能
   - 监控服务器响应时间

### 调试模式

在开发环境中，可以在浏览器控制台查看详细的验证过程:

```javascript
// 监听 CAPTCHA 事件
const widget = document.querySelector('cap-widget')
widget.addEventListener('solve', (e) => {
  console.log('CAPTCHA 完成:', e.detail.token)
})
```
